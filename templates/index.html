README.md: Why Split This Into 3 Pipelines Instead of One Script? project-04-llm-twin-system

If you cram scraping, chunking, vector indexing, LoRA fine-tuning, and FastAPI serving into one giant script, every web request ends up coupled to your training dependencies. I structured this repository around Paul Iusztin's Feature / Training / Inference (FTI) split so each stage only reads and writes well-defined artifacts on disk or in Qdrant.

Alongside the FTI pipeline, I implemented the core building blocks of modern open-weights models (`RMSNorm`, complex-valued `RoPE` rotary embeddings, `GroupedQueryAttention` with sliding window masking, and `SwiGLU`) in `src/llm_twin/components/llama_mistral_from_scratch.py` following Umar Jamil's PyTorch walkthroughs. Writing the tensor shapes by hand makes it obvious why `n_kv_heads=2` with `n_heads=8` cuts KV-cache RAM by 75% during long-context generation.

1. Feature Pipeline (`feature_pipeline.py`) Normalizes raw GitHub, Medium, and LinkedIn posts into `mongodb_warehouse.json`, splits text on sentence boundaries, and indexes vectors into Qdrant + BM25.
2. Training Pipeline (`training_pipeline.py`) Builds instruction-output pairs from the warehouse, applies low-rank adapters (`r=8, alpha=16`), and checks if validation ROUGE-L and style overlap beat the base model before saving.
3. Inference Pipeline (`inference_pipeline.py`) Runs 4 steps per query: intent classification, 3-query expansion + Qdrant/BM25 RRF retrieval, format drafting, and regex/token safety checks (blocking prompt injection strings and redacting email addresses).

User Guide & Step-by-Step Instructions Documentation

1. Searching & Generating Drafts (Tab 1: Query & A/B Console)

  • Click any of the three Sample Queries buttons at the top of Tab 1, or type your own technical question.
  • Use Draft Format to switch between a plain Technical Note, a LinkedIn Post draft (with hashtags), a Medium section, or a GitHub Architecture Decision Record (ADR).
  • Select Side-by-Side A vs. B Comparison under Routing Mode to run both Variant A (plain dense cosine similarity) and Variant B (3-query expansion + Qdrant + BM25 RRF) side by side.

2. Adding Your Own Articles or Code Notes (Tab 2: Document Index)

  • Open 2. Document Index, fill in a title and paragraph, and click Save & Index Document.
  • Your new note gets assigned a `[TWIN-DOC-xxx]` ID and is immediately searchable in Tab 1.

3. Testing LLaMA / Mistral Tensor Shapes (Tab 3: LLaMA / Mistral Shapes)

  • Change `n_heads` (e.g., `8`) and `n_kv_heads` (e.g., `2` or `4`) and click Run PyTorch Forward Check.
  • The table shows the exact KV-cache memory savings percentage, verifies that RoPE preserves L2 vector norms (`< 1e-4` drift), and confirms that tokens outside the sliding window have `0.0` attention weight.

4. Testing the JSON API (`/docs`)

  • Open Tab 8: API Console (/docs) to send live `GET` and `POST` requests to `/health`, `/telemetry`, `/twin-chat`, `/ab-duel`, and `/llama-diagnostics` right inside your browser without needing external CDN scripts.
