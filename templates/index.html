README.md - Architecture & Design Tradeoffs

Step 1 of 2
1. 3-Pipeline Split
2. Why Not LangChain

1. Feature / Training / Inference Split

Early prototypes mixed document scraping, vector indexing, and prompt formatting inside the FastAPI request handler. Splitting the project into three standalone stages fixed that:

  • Feature Pipeline (`src/llm_twin/pipelines/feature_pipeline.py`): Cleans markdown documents, splits them on paragraph boundaries, and writes vector chunks to `artifacts/feature_store/`.
  • Training Pipeline (`src/llm_twin/pipelines/training_pipeline.py`): Builds instruction pairs and runs a LoRA rank-8 adapter check before writing `evaluation_report.json`.
  • Inference Pipeline (`src/llm_twin/pipelines/inference_pipeline.py`): Expands the user query into 3 sub-queries, scores chunks with BM25 + Cosine + Overlap, and logs traces to JSONL.

2. Why We Dropped Heavy Orchestration Wrappers

When debugging retrieval misses, tracing through five layers of framework callbacks took longer than writing the 60-line retrieval scorer directly in Python. Keeping query expansion and cross-encoder scoring in plain Python also made it straightforward to log per-stage latency numbers (`query_expansion_ms`, `qdrant_search_ms`, `rerank_ms`) in every JSON response.
